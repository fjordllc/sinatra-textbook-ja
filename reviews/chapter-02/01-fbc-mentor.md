# 対象

- 第2章終了時点の `app.rb` と実行環境

# 総評

最小の文字列レスポンスから始め、二つのルートとリダイレクトへ進む流れは、初めてサーバー側を実装する学習者に適しています。特に、`redirect` を画面遷移ではなく二つのリクエストとして観察させる構成は、後の PRG 学習へ自然につながります。環境のバージョンと起動コマンドも一つに固定されています。

一方、公開版から読み始めた読者が、本文で前提にしているリポジトリを手元へ用意する手順がありません。FBC 内の案内を前提にせず、一冊で作業を開始できる入口が必要です。

# 良い点

- `get`、パス、ブロック、戻り値を `GET /movies` とレスポンスへ対応付けている。
- 起動中のターミナルが止まっているように見える理由と、変更後に再起動が必要なことを先回りしている。
- `GET /` の 302 と `GET /movies` の 200 を Network パネルとサーバーログの両方で確認できる。
- リダイレクトを先に体験させ、第8章で PRG という名前と目的を与える設計になっている。
- `bundle exec ruby app.rb` に起動方法を統一し、FBC のレビューで頻出する実行環境のずれを防いでいる。
- FBC の提出課題や提出方法を本文へ持ち込まず、一般向けの技術書として読める。

# 改善が必要な点

## must

### 作業用リポジトリを用意する入口がない

- 対象: `manuscript/part1/chapter2.md:36`
- 問題: 「リポジトリのルートには」と始まりますが、公開版を読んでいる人がどのリポジトリを取得し、どのディレクトリで作業するかが説明されていません。
- 理由: FBC 外の読者は `.ruby-version`、`Gemfile`、`Gemfile.lock` を持っておらず、`bundle install` から先へ進めません。
- 修正案: 第2章の環境確認前に、本書のリポジトリを clone してルートへ移動する手順を置く。章終了時点を確認するための Git タグがあることも、必要最小限で案内する。

## should

### Network パネルで見た二つのリクエストを言語化させる

- 対象: `manuscript/part1/chapter2.md:228`
- 問題: 表と説明を読めば流れは分かりますが、読者自身の観察結果を言葉にする確認がありません。
- 理由: FBC のレビューでは、302 が何を返し、誰が次の GET を送るのかを説明できることが重要です。
- 修正案: `/movies` の本文が最初のレスポンスに含まれるのではなく、ブラウザが二つ目の GET を送ると一文で説明させる短い確認を置く。

### ポートが使用中の場合の切り分けを一文だけ補う

- 対象: `manuscript/part1/chapter2.md:167`
- 問題: 前回起動したプロセスが残ると、初学者はコードの誤りと判断しやすいです。
- 理由: 起動直後の `Address already in use` は頻出しますが、本章では自力で切り分ける材料がありません。
- 修正案: 同じポートが使用中というエラーでは、別のターミナルで前のアプリが動いていないか確認する、と短く案内する。詳細は付録へ送る。

## could

### 変更箇所をより明示する

- 対象: `manuscript/part1/chapter2.md:208`
- 改善案: `get "/"` のブロックだけを置き換え、`get "/movies"` は残すと明記する。
- 期待される効果: 掲載されていない部分まで消してしまう初学者の操作ミスを防げます。
