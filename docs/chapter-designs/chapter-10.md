# 第10章 章設計: 見つからないものには 404 を返す

## この章の目的

存在しない URL と存在しない映画 ID に対して、404 ステータスと専用の 404 ページを返す。画面表示だけでなく、HTTP ステータスコードとして結果を確認する習慣を身につける。あわせて、映画図鑑の完成状態を確認する。

## 読了後にできるようになること

- 404 が「リソースが見つからない」ことを表す HTTP ステータスであると説明できる。
- 存在しない URL と、存在しない映画 ID を 404 として扱える。
- 404 と 500 の違いを説明できる。
- Sinatra の `not_found` ハンドラーを使って、存在しない URL の 404 ページを表示できる。
- 詳細・編集・更新・削除で映画が見つからない場合も 404 ページを返せる。
- 映画図鑑の完成状態を、ルーティング、ビュー、JSON 保存、入力チェック、エスケープ、CSS、起動方法から確認できる。

## 必要な前提知識

- 第6章までの `halt 404`。
- 第7章までの詳細・編集・削除ルート。
- Network タブでステータスコードを見る方法。

## サンプルアプリへ加える変更

- `views/not_found.erb` を追加する。
- `not_found do ... end` を追加し、存在しない URL で 404 ページを表示する。
- 映画が見つからない詳細・編集・更新・削除で、`status 404` と `erb :not_found` を返す。

## Network タブなどで観察する対象

- 存在しない URL の `404 Not Found`。
- 存在しない映画 ID の詳細画面の `404 Not Found`。
- 存在しない映画 ID の編集画面の `404 Not Found`。
- 意図的な例外による `500 Internal Server Error`。

## この章では扱わないこと

- 本格的な例外処理。
- 500 専用ページ。
- ログ監視やエラー通知。
- 入力値の詳細な検証。

## 章固有の設計判断

第10章では、第6章で一時的に使った文字列だけの 404 から、レイアウト付きの 404 ページへ進める。ただし、500 ページや本格的な例外処理は扱わない。

映画図鑑の CRUD はこの章で完成状態として確認する。第11章以降は、完成したアプリを使ってデバッグとファイル保存の限界を学ぶ。
