# 総評

フォームを「HTTP リクエストを作る HTML」として扱えており、FBC で重視する Network タブの観察にもつながっています。保存を第5章へ残し、この章では `params` に届くところまでに絞っているのも適切です。

一方で、章末の完成状態に `views/index.erb` と CSS の変更後コードがなく、第3章で改善した「章末で照合できる」方針が少し弱くなっています。また、`params.inspect` を使う一時的な実装を、完成機能ではないとさらに強めに説明した方がよいです。

# 良い点

- `GET /movies/new` と `POST /movies` を分け、表示と送信の違いを説明している。
- `id` と `name` の違いを明確に扱っている。
- Network パネルで Request Method、Request URL、Form Data、Response を見る観察がある。
- `POST /movies` で保存せず、次章への必要性を作れている。
- `content_type :text` にして、利用者入力を HTML として返さない配慮がある。

# 改善が必要な点

## must

### 章末の完成状態に一覧ビューと CSS が不足している

- 問題: 4.8 に `app.rb` と `views/new.erb` はあるが、変更した `views/index.erb` と CSS の最終形がない。
- 問題になる理由: 第4章では一覧へのリンク追加とフォーム CSS も読者が編集する。初学者が最終状態を照合できず、リンクや見た目の不具合を見落としやすい。
- 修正案: 4.8 に `views/index.erb` の完成コードと、CSS の追加部分または完成コードを掲載する。
- 対象箇所: 4.8

## should

### `params.inspect` が一時的な確認用コードであることを強調する

- 問題: 一時的な表示だとは書かれているが、章末の完成コードにも残るため、完成実装だと誤解される可能性がある。
- 問題になる理由: FBC の提出課題では、POST 後に `params.inspect` を返す実装のままでは不十分。次章で保存とリダイレクトに置き換える前提を強めたい。
- 修正案: 4.5 と 4.8 に「第5章で置き換える確認用コード」と明記する。
- 対象箇所: 4.5, 4.8

## could

### 空欄送信の確認を小さく入れる

- 改善案: タイトルを空欄で送ると `params["title"]` は空文字として届くことを観察させる。
- 期待される効果: 第5章のサーバー側入力チェックへ自然につながる。
- 対象箇所: 4.5 または 4.6

# 疑問点

- 第4章では `required` 属性を使わない方針で問題ない。第5章の入力チェックの学習効果を残せている。
