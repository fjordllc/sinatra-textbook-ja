# 第6章 章設計: 一覧と詳細でリソースを分ける

## この章の目的

映画の集合を表す `/movies` と、1 件の映画を表す `/movies/:id` を分ける。保存済み JSON から ID で 1 件を探し、詳細画面を表示する。登録成功後の遷移先も一覧から詳細へ変更する。

## 読了後にできるようになること

- `/movies` と `/movies/:id` の違いを、画面ではなくリソースの単位として説明できる。
- JSON から読み込んだ配列の中から、ID が一致する映画を探せる。
- 詳細画面で映画の全属性を安全に表示できる。
- 一覧から詳細へ移動するリンクを作れる。
- 存在しない ID に対して 404 を返せる。
- 登録成功後に、作成した映画の詳細画面へリダイレクトできる。

## 必要な前提知識

- 第5章の JSON 読み書き、UUID、`h` ヘルパー。
- Ruby の `find` とブロックの基本。
- ERB でリンクの `href` に値を埋め込む方法。

## サンプルアプリへ加える変更

- `find_movie(id)` を追加し、ID が一致する映画を探す。
- `GET /movies/:id` を追加し、詳細画面を表示する。
- `views/show.erb` を追加する。
- 一覧に「詳細」リンクを追加する。
- 存在しない ID のとき、`halt 404, "映画が見つかりません"` を返す。
- `POST /movies` の成功後リダイレクト先を `/movies` から `/movies/:id` へ変更する。
- 詳細画面の表示にも `h` ヘルパーを使う。
- 紹介文の改行表示に `white-space: pre-line` を使う。

## Network タブなどで観察する対象

- 一覧表示の `GET /movies`。
- 詳細表示の `GET /movies/:id`。
- 登録成功時の `POST /movies`、303、`GET /movies/:id`。
- 存在しない ID へアクセスしたときの 404。

## この章では扱わないこと

- 編集と削除。
- 404 用の専用 HTML ページ。第10章で扱う。
- 詳しい REST 理論。
- 検索、並び替え、ページネーション。
- XSS の攻撃例の実演。第9章で扱う。

## 章固有の設計判断

一覧画面にはタイトル、公開年、ジャンル、詳細リンクだけを表示する。監督と紹介文は詳細画面に表示し、一覧と詳細を分ける意味を残す。

第5章で導入した `h` ヘルパーを、詳細画面でもすべての利用者入力に使う。紹介文の改行は Ruby 側で `<br>` を挿入せず、CSS の `white-space: pre-line` で扱う。
