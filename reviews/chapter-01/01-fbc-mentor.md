# 総評

Web アプリケーションを画面ではなくリクエストとレスポンスの往復として捉える主張が明確です。FBC で頻出する「コードと画面だけを見て Network パネルを見ない」という状態を、第1章から防ぐ構成になっています。REST や Rack の理論へ広げず、次章の Sinatra 実装へ必要な見取り図に絞っている点も学習段階に合っています。

# 良い点

- `/movies` をファイル名と決め付けず、サーバー側の処理へ結び付けられることを早い段階で説明している。
- ブラウザ、サーバー、リクエスト、レスポンスを図、HTTP メッセージ、映画一覧の具体例で重ねて説明している。
- HTTP/1.1 の例を使いながら、HTTP/2 と HTTP/3 の詳細へ進まない境界が明確である。
- 静的な HTML も Web サーバーから返せることを示し、「静的 HTML は Web ではない」という誤解を避けている。
- Network パネルで最初に見る項目を三つに絞り、全ヘッダーの理解を要求していない。
- 本文は FBC の課題や提出方法を前提にせず、一般向けの技術書として読める。

# 改善が必要な点

## must

### Network パネルを観察できる URL の条件が不足している

- 対象: `manuscript/part1/chapter1.md:151`
- 問題: 「今ブラウザで開いている本書のページ」が `file://` で開かれている場合、本文が期待する HTTP の `Status Code` やレスポンスヘッダーを同じ形で確認できません。
- 理由: この観察は章の学習ゴールそのものです。読者の開き方によって進行不能になる条件を残せません。
- 修正案: `http://` または `https://` で開いていることを確認させる。`file://` の場合は、公開版を開くか `mdbook serve` の URL を使うよう案内する。

## should

### DevTools を開く具体的な手順を補う

- 対象: `manuscript/part1/chapter1.md:153`
- 問題: 「DevTools を開く」で手順が一段省略されています。
- 理由: HTML/CSS を学習済みでも、DevTools の利用経験があるとは限りません。
- 修正案: macOS と Windows/Linux のショートカット、または Chrome メニューから開く経路を一度だけ示す。

### はじめにの略語を読者の行動へ言い換える

- 対象: `manuscript/preface.md:21`
- 問題: `CRUD`、`PRG`、`XSS` が説明前に連続します。
- 理由: 学習項目の一覧であっても、未知語が並ぶと本書の到達点を想像しにくくなります。
- 修正案: 「データの作成・読み取り・更新・削除（CRUD）」「再送信を防ぐ PRG パターン」「入力を安全に表示する XSS 対策」のように目的を添える。

## could

### Network パネルの観察結果を一文で言語化させる

- 対象: `manuscript/part1/chapter1.md:172`
- 改善案: 実際に見つけた URL、メソッド、ステータスコードを使い、「ブラウザは何を送り、何が返ったか」を一文で書かせる。
- 期待される効果: メンターが確認する「なぜそう動くか」の説明へ早い段階からつながる。
