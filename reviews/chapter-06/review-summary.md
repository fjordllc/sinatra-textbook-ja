# レビュー統合

## 対象

第6章「一覧と詳細でリソースを分ける」

## 総評

6 観点すべてで、章の目的と範囲は妥当と判断された。未解決の `must` はない。一覧と詳細をリソース単位で分け、ID 検索、詳細画面、404、登録後の詳細リダイレクトへ進む構成は、第7章の編集・削除に必要な前提を作れている。

## must

なし。

## should

- ルート順の重要性を、具体的なルートを先、変化するルートを後という形で補足する。採用。
- 第6章で追加した CSS の完成コードを章末に載せる。採用。
- `find_movie` が毎回 JSON を読み込むことの意図と限界を補足する。採用。
- 狭幅時に詳細画面の定義リストを 1 列へ切り替える CSS を追加する。採用。
- `halt` が処理を止めてステータスコードと本文を返すことを説明する。採用。
- 次章では詳細画面から編集・削除へ進むことを橋渡しとして追記する。採用。

## could

- 詳細リンクを「詳細を見る」にする案は採用しない。表の操作列では短い「詳細」で十分であり、画面の密度を保つ。
- `find` の図解は採用しない。本文とコードで十分追えるため。
- `halt 404` の本文がプレーンテキストである補足は、専用 404 ページを扱う第10章に回す。

## 対応後の確認観点

- `app.rb` と本文の完成コードで、`/movies/new` が `/movies/:id` より前にあること。
- CSS の実ファイルと本文の追加コードが一致していること。
- 登録成功後に `GET /movies/:id` へ移動すること。
- 存在しない ID が 404 を返すこと。
