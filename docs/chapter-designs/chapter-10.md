# 第10章 章設計: 見つからないものには 404 を返す

## この章の目的

存在しない URL と存在しない映画 ID に対して、Sinatra 標準の表示と既存の `halt` が 404 ステータスを返すことを観察する。画面表示だけでなく、HTTP ステータスコードとして結果を確認する習慣を身につける。あわせて、映画図鑑の完成状態を確認する。

## 読了後にできるようになること

- 404 が「リソースが見つからない」ことを表す HTTP ステータスであると説明できる。
- 存在しない URL と、存在しない映画 ID を 404 として扱える。
- 404 と 500 の違いを説明できる。
- 存在しない URL には、Sinatra が標準で404を返すことを説明できる。
- 詳細・編集・更新・削除で映画が見つからない場合に、既存の `halt` が404を返すことを説明できる。
- 映画図鑑の完成状態を、ルーティング、ビュー、JSON 保存、エスケープ、CSS、起動方法から確認できる。

## 必要な前提知識

- 第6章までの `halt 404`。
- 第7章までの詳細・編集・削除ルート。
- Network パネルでステータスコードを見る方法。

## サンプルアプリへ加える変更

完成コードに残す変更はない。500の確認用ルートだけを一時的に追加し、観察後に削除する。

## Network パネルなどで観察する対象

- 存在しない URL の `404 Not Found`。
- 存在しない映画 ID の詳細画面の `404 Not Found`。
- 存在しない映画 ID の編集画面の `404 Not Found`。
- 意図的な例外による `500 Internal Server Error`。

## この章では扱わないこと

- 本格的な例外処理。
- 500 専用ページ。
- ログ監視やエラー通知。
- 入力値の詳細な検証。

## 章固有の設計判断

第10章では、Sinatra 標準の404と、第6・7章の短いメッセージを返す `halt` を観察する。専用のエラーページや本格的な例外処理は追加しない。

映画図鑑の CRUD はこの章で完成状態として確認する。第11章以降は、完成したアプリを使ってデバッグとファイル保存の限界を学ぶ。
