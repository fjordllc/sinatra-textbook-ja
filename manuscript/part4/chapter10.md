# 第10章 見つからないものには 404 を返す

第9章では、利用者入力をそのまま HTML にしないことを学びました。この章では、URL で指定されたものが見つからない場合を扱います。

Sinatra 標準の 404 と、すでに書いた `halt` の動きを観察し、アプリのバグによる 500 との違いを確認します。最後に、ここまで作ってきた映画図鑑の完成状態も見直します。

## 10.1 404 は「見つからない」というレスポンス

404 は、リクエストされたリソースが見つからないことを表す HTTP ステータスコードです。

映画図鑑では、次のような場合に 404 を返します。

- 存在しない URL にアクセスした。
- 存在しない映画 ID の詳細画面にアクセスした。
- 存在しない映画 ID の編集画面にアクセスした。
- 存在しない映画 ID を更新・削除しようとした。

大事なのは、画面に「見つかりません」と表示することだけではありません。HTTP レスポンスのステータスコードが 404 になっていることです。

## 10.2 Sinatra 標準の 404 を確認する

アプリを起動して、`/unknown` にアクセスしてください。どのルートにも一致しない URL には、Sinatra が標準で 404 を返します。Network パネルで `404 Not Found` を確認します。このためにルートやテンプレートを追加する必要はありません。

## 10.3 存在しない映画 ID を確認する

`/movies/not-found` は `/movies/:id` に一致しますが、指定した ID の映画がありません。この場合には、第6章で書いた次の 1 行が処理を止めます。

```ruby
halt 404, "映画が見つかりません" if @movie.nil?
```

`halt` は、その場でリクエストの処理を終えてレスポンスを返します。映画が見つからない場合に詳細テンプレートを実行しないための、最小限の処理です。編集・更新・削除にも、第7章で同じ形の処理を入れています。

`/movies/not-found` にアクセスし、メッセージと Network パネルの `404 Not Found` を確認してください。

本書では、この短いメッセージと Sinatra 標準の表示を使います。専用の 404 ページや、エラーの種類による表示の出し分けは完成条件に含めません。エラー画面の設計や入力エラーからの復帰は、Rails でアプリケーションを作る段階で学びます。

## 10.4 404 と 500 の違い

404 は、リクエストされたリソースが見つからないことを表します。

一方、500 は、サーバー側で予期しないエラーが起きたことを表します。

例えば、`app.rb` の末尾に一時的に次のようなルートを追加すると、アクセス時に例外が発生します。

```ruby
get "/error-example" do
  raise "確認用のエラー"
end
```

このルートへアクセスすると、アプリの中で例外が起きます。これは「見つからない」ではなく、サーバー側のエラーです。Network パネルでは `500 Internal Server Error` として確認できます。

この確認用ルートは、動作確認が終わったら必ず削除してください。映画図鑑の完成コードには残しません。

## 10.5 映画図鑑の完成状態を確認する

ここまでで、映画図鑑には次の機能が揃いました。

| 機能 | ルート |
| --- | --- |
| トップから一覧へ移動 | `GET /` |
| 一覧表示 | `GET /movies` |
| 新規登録画面 | `GET /movies/new` |
| 登録処理 | `POST /movies` |
| 詳細表示 | `GET /movies/:id` |
| 編集画面 | `GET /movies/:id/edit` |
| 更新処理 | `PATCH /movies/:id` |
| 削除処理 | `DELETE /movies/:id` |
| 存在しない URL | 404 |
| 存在しない映画 ID | 404 |

完成状態では、次のファイルがあります。

```text
.
├── app.rb
├── data/
│   └── movies.json
├── public/
│   └── stylesheets/
│       └── application.css
└── views/
    ├── edit.erb
    ├── index.erb
    ├── layout.erb
    ├── new.erb
    └── show.erb
```

起動に必要な環境ファイルも確認します。

```text
.
├── .ruby-version
├── Gemfile
└── Gemfile.lock
```

確認する観点は次のとおりです。

- `bundle exec ruby app.rb` で起動できる。
- 映画データは `data/movies.json` に保存される。
- `data/movies.json` は `public/` に置かれていない。
- ID は `SecureRandom.uuid` で作られる。
- 登録、更新、削除の後はリダイレクトする。
- HTML フォームの PATCH、DELETE は `_method` を使う。
- 利用者入力は `h` ヘルパーで表示される。
- 紹介文の改行表示は CSS の `white-space: pre-line` で扱う。
- 存在しない URL と存在しない映画 ID は 404 になる。

この時点で、映画図鑑は小さな CRUD アプリケーションとして一通り動きます。第11章からは、動かないときにどこを見るかを学びます。

次章では、画面表示、Network パネル、Sinatra のログ、JSON ファイルを分けて見ながら、問題がどこで起きているかを切り分けます。

## 確認しよう

1. `/unknown` にアクセスし、Sinatra 標準の表示と `404 Not Found` を確認する。
2. `/movies/not-found` にアクセスし、短いメッセージと `404 Not Found` を確認する。
3. 一時的な `/error-example` ルートで 500 を確認し、確認後に必ず削除する。
4. 映画図鑑の完成状態のファイル、ルート、主要機能を照合する。

この章で完成コードに追加する処理はありません。第7章までの CRUD と第9章のエスケープを使って、次章のデバッグへ進みます。

## 考えてみよう

- なぜ見つからない映画 ID を空の詳細画面として表示しないのでしょうか。
- 404 と 500 は、どちらもエラーに見えますが、何が違うのでしょうか。
- 画面にエラーメッセージが出ていても、Network パネルでステータスコードを見る必要があるのはなぜでしょうか。

## さらに学ぶ

エラー処理をさらに学ぶときは、「要求したものがない状態」と「サーバー内部で処理に失敗した状態」を分けて追います。

## 参考資料

- [MDN 404 Not Found](https://developer.mozilla.org/ja/docs/Web/HTTP/Status/404)では、サーバーへ到達していても対象のリソースが見つからない状態を学べます。
- [MDN 500 Internal Server Error](https://developer.mozilla.org/ja/docs/Web/HTTP/Status/500)では、サーバー側で予期しない失敗が起きたときの一般的な応答を学べます。
- [Sinatra 公式ドキュメント](https://sinatrarb.com/intro.html)では、`halt`、`not_found`、`error` を使い、状態ごとにレスポンスを分ける方法を確認できます。
