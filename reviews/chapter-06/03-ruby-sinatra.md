# 対象

第6章「一覧と詳細でリソースを分ける」

# 総評

コードは初学者向けとして簡潔で、ID 検索、詳細表示、404、登録後リダイレクトが自然に実装されている。`/movies/new` と `/movies/:id` の順序にも触れており、Sinatra のルーティング上の重要点を押さえている。

# 良い点

- `find_movie` で JSON から読み込んだ配列を検索する実装が読みやすい。
- `halt 404` を使い、見つからない ID を 404 として返している。
- ルート順の注意が本文にある。
- 詳細画面でも `h` を使い、保存済み利用者入力を安全に表示している。
- 登録後のリダイレクト先を、作成した `movie["id"]` から組み立てている。

# 改善が必要な点

## must

なし。

## should

- 問題: `find_movie` は呼び出すたびに JSON ファイルを読み直すが、その意図や限界に触れていない。
- 理由: 第6章の規模では問題ないが、読者が効率のよい設計だと誤解する可能性がある。
- 修正案: この章では分かりやすさを優先して毎回読み込み、ファイル保存の限界は第12章で扱うと短く補足する。

## could

- 改善案: `halt 404, ...` の本文がプレーンテキストであることを補足してもよい。
