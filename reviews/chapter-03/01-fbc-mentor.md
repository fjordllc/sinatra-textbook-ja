# レビュー担当

FBC ベテランメンター

# 対象

第3章「HTML をレスポンスとして返す」

- 原稿: `manuscript/part2/chapter3.md`
- コード: `app.rb`, `views/layout.erb`, `views/index.erb`, `public/stylesheets/application.css`
- 章設計: `docs/chapter-designs/chapter-03.md`

# 総評

第2章の文字列レスポンスから、HTML、ERB、レイアウト、静的ファイルへ進む流れは自然です。FBC でよく起きる `layout.erb` の役割の誤解や、`public/` への保存データ配置の誤解を早い段階で扱えている点も良いです。

一方で、初学者が章末時点の正しい状態を照合するには、`app.rb` 以外の完成コードが不足しています。FBC のレビューでは「どのファイルに何を書くのか」を確認できることが重要なので、章末の完成状態をもう少し明確にする必要があります。

# 良い点

- `layout.erb` に `html`、`head`、`body` を置き、個別ビューに重複させない説明がある。
- `public/` は直接参照できる静的ファイルの置き場所だと説明し、保存用 JSON を置かない前振りがある。
- 映画一覧にタイトル、公開年、ジャンルだけを表示し、詳細画面の意味を残している。
- 架空の映画データを使っており、権利物の転載リスクが低い。
- Network パネルで HTML と CSS が別リクエストになることを確認させている。

# 改善が必要な点

## must

### 章末の完成状態が `app.rb` に偏っている

- 問題: 3.10 で完成コードとして `app.rb` だけを示しており、`views/layout.erb`、`views/index.erb`、`public/stylesheets/application.css` の最終形を確認できない。
- 問題になる理由: 初学者は途中の小さな変更を重ねたあと、最終的に自分のファイルが正しいか判断しにくい。特に `layout.erb` と個別ビューの責務はレビューでも頻出する確認点である。
- 修正案: 3.10 に章終了時点の `views/layout.erb`、`views/index.erb`、CSS の最終形を追加する。CSS 全文が長い場合でも、この章の CSS は短いため掲載してよい。
- 対象箇所: `manuscript/part2/chapter3.md` 3.10

## should

### 作業開始位置を明示した方がよい

- 問題: 第3章をどのタグまたはどの状態から始めるかが本文冒頭に明示されていない。
- 問題になる理由: 読者が `main` の最新状態から作業を始めると、章の手順と手元のファイルが食い違う可能性がある。
- 修正案: 冒頭で「第2章から続けている場合はそのまま進む。新しく始める場合は `chapter-02` タグから作業用ブランチを作る」と短く示す。
- 対象箇所: 3章冒頭

### エスケープを後で扱うことを短く予告した方がよい

- 問題: `<%= movie["title"] %>` を値の出力として教えているが、利用者入力を出すときの注意がまだ出てこない。
- 問題になる理由: 第6章で `h` ヘルパーを導入する方針は妥当だが、この章だけ読むと `<%= %>` で利用者入力をそのまま出す書き方が一般に安全だと誤解される可能性がある。
- 修正案: この章の映画データは教材が用意した固定データであり、利用者が入力した値を表示するときは第6章以降でエスケープを扱う、と一文添える。
- 対象箇所: 3.5 または 3.10

## could

### 章末の確認を一文で締める

- 改善案: `app.rb`、`layout.erb`、`index.erb` の役割を読者自身が一文で説明する小さな確認を、3.10 の末尾に置く。
- 期待される効果: 第3章の学習ゴールが、コード写経ではなく責務の理解として定着する。
- 対象箇所: 3.10
