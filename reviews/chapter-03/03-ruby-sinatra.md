# レビュー担当

Ruby・Sinatra・Rack に詳しい技術者

# 対象

第3章「HTML をレスポンスとして返す」

- 原稿: `manuscript/part2/chapter3.md`
- コード: `app.rb`, `views/layout.erb`, `views/index.erb`, `public/stylesheets/application.css`
- 章設計: `docs/chapter-designs/chapter-03.md`

# 総評

Sinatra の ERB、既定の `views/`、既定の `layout.erb`、`public/` の静的ファイル配信について、公式ドキュメントと整合する説明になっています。Classic Style の小さなアプリとして、トップレベルのローカル変数 `movies` をルートブロックから参照する実装も、この段階では単純で理解しやすいです。

技術的な注意点として、ERB の `<%= %>` は自動エスケープではありません。この章では固定データなので重大な脆弱性にはなりませんが、後章の XSS への布石として、固定データと利用者入力の違いを明示した方が安全です。

# 良い点

- `erb :index` が `views/index.erb` を使うこと、`views/layout.erb` が既定のレイアウトになることを正しく説明している。
- `public/stylesheets/application.css` が `/stylesheets/application.css` で取得される説明が正しい。
- `bundle exec ruby app.rb` の起動方法を崩していない。
- `enable :method_override` や `Rack::Utils.escape_html` を、この章で先取りしていない。
- `GET /movies` と CSS の `GET` を分けて観察させている。

# 改善が必要な点

## must

### ERB の出力が自動エスケープではないことへの橋渡しが必要

- 問題: `<%= movie["title"] %>` を「HTML に出力する」と説明しているが、HTML として解釈される文字を含む値をどう扱うかに触れていない。
- 問題になる理由: Sinatra の ERB は Rails のビューのような自動エスケープを前提にできない。利用者入力を後で扱う教材として、ここで安全性の前提を曖昧にすると第6章以降の `h` ヘルパー導入が唐突になる。
- 修正案: 「この章のデータは教材内で用意した固定データなのでそのまま出力している。利用者が入力した値を表示するときは HTML として解釈されないようにエスケープする必要があり、第6章で扱う」と明記する。
- 対象箇所: 3.5

## should

### `movies` がローカル変数としてルートから参照できる理由は深掘りしない方針でよいが、配置は補足したい

- 問題: `movies` を `require "sinatra"` の下に置く理由が説明されていない。
- 問題になる理由: 初学者がルートブロックの中に毎回配列を書く、または `get "/movies"` より下に置いても同じと考える可能性がある。
- 修正案: この章では「起動時に用意する仮のデータ」として `require "sinatra"` の下、ルート定義の前に置く、と短く説明する。スコープの詳説は不要。
- 対象箇所: 3.5

### Sinatra の `Content-Type` は実測結果に合わせて表現する

- 問題: 3.9 では `Content-Type` を確認するとだけ書いており、期待値が明示されていない。
- 問題になる理由: 読者が何を見ればよいか判断しにくい。
- 修正案: `GET /movies` は `text/html;charset=utf-8`、CSS は `text/css;charset=utf-8` のような値が表示される、と実測に合わせて書く。ただし環境差があり得るため「たとえば」と添える。
- 対象箇所: 3.9

## could

### `erb :index` と文字列引数の違いを公式挙動として補足する

- 改善案: Sinatra では `erb :index` のようにシンボルで指定するとテンプレート名になり、文字列を渡すとテンプレート内容として扱われる、と短く補足する。
- 期待される効果: テンプレート名にシンボルを使う理由が少し明確になる。
- 対象箇所: 3.2

# 疑問点

- 第6章で `h` ヘルパーを導入するなら、第3章の固定データは意図的に安全な文字列だけにしておく現方針で問題ない。
