# 第12章 章設計: ファイル保存の先にデータベースがある

## この章の目的

映画図鑑で使った JSON ファイル保存を振り返り、Web アプリケーションの基本を学ぶには十分だった一方で、同時更新、データ量、関連、整合性を扱うには限界があることを理解する。

## 読了後にできるようになること

- 映画図鑑で実装した CRUD、HTTP メソッド、PRG、XSS 対策、404 を振り返れる。
- JSON ファイル保存が、1 ファイル全体の読み書きで成り立っていることを説明できる。
- 同時書き込み、データ量、関連、整合性の観点から、ファイル保存の限界を説明できる。
- ER 図や正規化をこの章で扱わない理由を理解できる。
- Rails や Active Record で隠れやすい処理を、本書で体験した処理と結びつけられる。

## 必要な前提知識

- 第11章までの映画図鑑の完成状態。
- `data/movies.json` を読み書きして CRUD を実現したこと。
- REST を意識した URI、HTTP メソッド、PRG、XSS 対策、404 の基本。

## サンプルアプリへ加える変更

完成コードに残す変更は行わない。この章では、映画図鑑を実用アプリへ拡張するのではなく、本書の学習範囲を振り返る。

## 観察する対象

- `load_movies` と `save_movies` が 1 ファイル全体を読み書きしていること。
- `data/movies.json` が映画の配列として保存されていること。
- 1 件の更新・削除でも配列全体を書き戻していること。
- 映画に監督、ジャンル、レビューなどの関連を追加したくなった場合に、JSON の構造が複雑になること。

## この章では扱わないこと

- ER 図の描き方。
- 正規化。
- SQL。
- Active Record の具体的な使い方。
- Rails アプリケーションの作成。
- SQLite や PostgreSQL の導入手順。

## 章固有の設計判断

本章は、データベースを教える章ではなく、データベース設計へ進む理由を作る章とする。映画図鑑を最後まで完成させたうえで、完成品として飾るのではなく、Web アプリケーションの基本構造を理解するための教材だったと位置付ける。
