# レビュー担当

FBC ベテランメンター

# 対象

第9章「利用者の入力はそのまま HTML にしない」

# 総評

FBC のレビューで重視される XSS 対策を、映画図鑑の文脈で自然に扱えている。危険なコードを一時的な確認に閉じ、完成コードに残さない方針も適切である。

# 良い点

- 利用者入力がタイトルだけでなく全属性であることを明確にしている。
- `<script>`、属性値、`textarea` の 3 種類を扱っており、単純な禁止ワード対策に流れていない。
- `Rack::Utils.escape_html` を明示的に使う方針が保たれている。
- `gsub("\n", "<br>")` を避け、CSS で改行表示する説明がある。

# 改善が必要な点

## must

なし。

## should

- 問題: 危険なコードを試す手順があるため、確認前に JSON を退避するなどの安全策を一言入れた方がよい。
- 理由: 確認用の危険な入力がデータに残ったまま次章へ進む可能性がある。
- 修正案: 確認後に `data/movies.json` から確認用データを消す、または元に戻すと明記する。

## could

- 改善案: FBC 固有の提出課題には触れない現在の方針でよい。
