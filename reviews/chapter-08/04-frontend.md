# レビュー担当

フロントエンドエンジニア

# 対象

第8章「リダイレクトは二つのリクエストをつなぐ」

# 総評

ユーザー操作、ブラウザが送るリクエスト、サーバーのログを分けて観察する構成がよい。フォームの制約と Network タブの見え方が整理されている。

# 良い点

- HTML フォームが PATCH/DELETE を直接送れないことを再確認している。
- Network タブの Form Data に `_method` を見る説明がある。
- 再読み込み時に表示中の GET が送られることを、ユーザー操作として確認できる。
- 削除後の一覧表示と再読み込みの説明が自然である。

# 改善が必要な点

## must

なし。

## should

- 問題: Network タブでリダイレクト前後を見るには、ログが消えない設定や Preserve log が必要になることがある。
- 理由: 初学者が画面遷移後に最初の POST を見失う可能性がある。
- 修正案: 必要に応じて Network タブの Preserve log を有効にすると、リダイレクト前後を追いやすいと補足する。

## could

- 改善案: スクリーンショットはこの段階では必須ではない。
