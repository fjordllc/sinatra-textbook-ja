# レビュー担当

Ruby・Sinatra・Rack に詳しい技術者

# 対象

第5章「JSON ファイルに映画を保存する」

# 総評

Ruby と Sinatra の使い方は初学者向けとして自然である。`json`、`securerandom`、`rack/utils` を明示的に読み込んでおり、偶然動く環境へ依存していない。保存データを 1 ファイルの JSON 配列として扱う方針も、次のデータベース設計へ進む前の教材として妥当である。

# 良い点

- `SecureRandom.uuid` により、タイトルや配列位置を ID にしない方針が守られている。
- 利用者入力をファイルパスへ埋め込まず、単一の JSON ファイルを読み込んでいる。
- `Rack::Utils.escape_html` を明示的に使う `h` ヘルパーにより、ERB の暗黙的な自動エスケープに依存していない。
- `movie_params` で保存対象のキーを明示しており、`params` 全体をそのまま保存していない。
- `redirect "/movies"` の実際のレスポンスが 303 であることに本文が追随している。

# 改善が必要な点

## must

なし。

## should

- 問題: `JSON.parse(File.read(MOVIES_FILE))` は教材として簡潔だが、ファイルがない場合や壊れている場合の扱いをしないことが本文に明示されていない。
- 理由: 章の範囲外であることを示さないと、読者が自分の環境で JSON を壊したときに教材のコードが不十分に見える可能性がある。
- 修正案: この章ではリポジトリに `data/movies.json` がある前提で進め、壊れた JSON の復旧はよくあるエラーやデバッグ章で扱う、と短く補足する。

## could

- 改善案: `File.write` がファイル全体を書き換えることを、コード直後にもう一文強調してもよい。
- 期待される効果: 第12章のファイル保存の限界へつながりやすい。

# 疑問点

- Sinatra の `redirect` が POST 後に 303 を返す挙動は固定バージョンで確認済みであり、第8章では「明示的に変更」ではなく「意味付け」として扱う方がよい。
