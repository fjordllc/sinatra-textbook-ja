# レビュー担当

技術書のベテラン編集者

# 対象

第5章「JSON ファイルに映画を保存する」

# 総評

章の目的は明確で、保存されない状態から JSON へ保存する流れが段階的に説明されている。コードの完成形も提示されており、読者が自分の状態を照合できる。

# 良い点

- 冒頭で第4章の到達点と第5章の課題がつながっている。
- `data/movies.json`、`load_movies`、`save_movies`、`movie_params` の順に、抽象化が過度にならない範囲で整理されている。
- エラー時と成功時の画面遷移が別々に説明されている。
- 完成コードが `app.rb`、`views/index.erb`、`views/new.erb`、CSS まで掲載されている。
- 「この章ではまだ PRG と呼ばない」という設計上の留保が明確である。

# 改善が必要な点

## must

なし。

## should

- 問題: `MOVIES_FILE` の説明で `File.join` の意図は説明されているが、`__dir__` を使う理由がやや短い。
- 理由: 実行する場所によって相対パスの基準が変わることを知らない読者には、`File.join(__dir__, ...)` が儀式に見える可能性がある。
- 修正案: 「どのディレクトリから起動しても `app.rb` から見た `data/movies.json` を指す」と補足する。

## could

- 改善案: 章末の「考えてみよう」に、保存とリダイレクトが分かれている理由を問う設問を追加してもよい。
- 期待される効果: 第8章の PRG への橋渡しが強くなる。

# 疑問点

- 第9章で XSS を実演する前に `h` を導入しているため、第9章では「安全なコードを一時的に外す」説明を丁寧にする必要がある。
