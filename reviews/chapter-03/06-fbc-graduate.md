# 総評

FBC 受講時につまずきやすい「Sinatra が HTML ファイルを探してそのまま返すのではなく、ルートからテンプレートを描画する」という点が自然に説明されています。`layout.erb` と `public/` の扱いも、レビューでよく指摘される内容を先に学べる構成です。

実務につながる観点では、ビューに表示する値が将来は利用者入力になることへの注意をこの章で短く入れるべきです。第6章で本格的にエスケープを扱う方針は良いですが、ここで `<%= %>` の意味を「安全に出す」ではなく「結果を出力する」と正確に位置付ける必要があります。

# 良い点

- Sinatra のテンプレート機能を、Web アプリケーションの画面生成として説明している。
- `public/` と保存データの置き場所を早めに区別している。
- 映画一覧にすべての属性を出さず、画面の責務を考えさせている。
- CSS を必要最小限に留めており、主題がぶれていない。
- Network パネルで HTML と CSS の取得を観察する流れがある。

# 改善が必要な点

## must

### `<%= %>` とエスケープの関係を曖昧にしない

- 問題: `<%= %>` を使うと値が HTML に出力される、という説明だけでは、利用者入力をそのまま出してよいと受け取られる可能性がある。
- 問題になる理由: Sinatra で初学者が作る CRUD アプリでは、XSS 対策の漏れが重要なレビュー観点になる。この章で危険な例を扱う必要はないが、後で扱うことへの橋渡しは必要。
- 修正案: この章では教材が用意した固定データを扱うためそのまま表示している、利用者が入力した値は第6章以降でエスケープして表示する、と明記する。
- 対象箇所: 3.5

## should

### `Content-Type` の観察結果を具体化する

- 問題: Network パネルで `Content-Type` を確認するとあるが、HTML と CSS で何が違えばよいかが書かれていない。
- 問題になる理由: HTTP を観察する習慣を付けるには、見るべき値が具体的である必要がある。
- 修正案: HTML は `text/html`、CSS は `text/css` を含む `Content-Type` になる、と説明する。
- 対象箇所: 3.9

### 最終状態の照合を強くする

- 問題: 章末で `app.rb` 以外の最終コードがない。
- 問題になる理由: この章はビュー構成が主題なので、`layout.erb` と `index.erb` の完成状態が見えないとレビューしにくい。
- 修正案: 3.10 にビューと CSS の最終コードを追加する。
- 対象箇所: 3.10

## could

### ターミナルログを見る習慣を軽く入れる

- 改善案: ERB の構文エラーが出たときは、ブラウザの 500 だけでなく起動中のターミナルログを見る、と一文入れる。
- 期待される効果: 第11章のデバッグへ自然につながる。
- 対象箇所: 3.5 または 3.10

# 疑問点

- この章では `h` ヘルパーを入れない方針でよい。固定データの段階で先に抽象化を入れると、ERB とレイアウトの理解が散る。
