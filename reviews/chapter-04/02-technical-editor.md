# 総評

章の目的は明確です。`action`、`method`、`name` の順に説明し、映画フォームへ拡張してから `params` と Network パネルで確認する構成は、初学者にとって自然です。扱わない範囲もおおむね守られています。

改善点は、本文中の「フォームは GET と POST が基本」という表現の正確さと、章末の照合情報です。HTML 仕様上の `dialog` に触れているため、本文側でも誤解を避ける表現にするとよいです。

# 良い点

- 冒頭に「保存ではなく、リクエストと `params` の確認」と目的を明示している。
- 最小フォームから映画フォームへ進む流れが分かりやすい。
- `id`、`label for`、`name` の役割を分けて説明している。
- `POST` だけで保存されるわけではない、という重要な誤解を潰している。
- 参考資料がフォームと POST に絞られている。

# 改善が必要な点

## must

### 章末で変更ファイルを照合しきれない

- 問題: 4.8 の「追加・変更したもの」に `views/index.erb` と CSS があるが、完成コードは示されていない。
- 問題になる理由: 本書では章末で完成状態を確認できる方針を採っている。フォーム章では `new.erb` だけでなく、導線と CSS も完成状態の一部である。
- 修正案: `views/index.erb` の完成コードと、CSS の追加部分を掲載する。
- 対象箇所: 4.8

## should

### HTML フォームの `method` 説明を少し正確にする

- 問題: 「HTML フォームでは、`method` に `get` または `post` を指定してリクエストを送るのが基本」とあるが、章末の「さらに学ぶ」で `dialog` に触れているため、読者によっては矛盾に見える。
- 問題になる理由: 仕様上の例外に触れるなら、本編では「HTTP リクエストとして送る場合は」と限定した方が技術的に正確。
- 修正案: 4.7 を「HTTP リクエストとしてサーバーへ送るフォームでは、`get` または `post` を使う」と修正する。
- 対象箇所: 4.7

### 第4章の一時状態であることを章末にも置く

- 問題: 章末コードに `params.inspect` が出るため、完成アプリの一部に見えやすい。
- 問題になる理由: 次章でこのコードが置き換わることを、章末でも明確にした方がよい。
- 修正案: `post "/movies"` のコード直後に「これは第4章だけの確認用レスポンス」と注記する。
- 対象箇所: 4.8

## could

### `application/x-www-form-urlencoded` は本文中で深入りしない

- 改善案: 現状の扱いでよい。第4章では名前だけ確認し、形式の詳細は「さらに学ぶ」へ送る。
