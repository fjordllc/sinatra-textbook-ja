# 総評

`get "/movies"` のどこが HTTP メソッドで、どこがパスなのかを表で確認できたので、短いコードでも何をしているか分かりました。起動後にターミナルへ入力できなくなる理由や、コードを変えるたびに再起動することも書かれていて、待ち状態をエラーだと勘違いせず進められます。

ただし、「リポジトリのルート」が自分のどのフォルダなのか分かりませんでした。公開された本だけを読んでいる場合、三つのファイルが手元にないため、最初のコマンドまで進めません。

# 良い点

- 最初に返すものが短い文字列だけなので、ルートと画面表示の対応へ集中できる。
- `ruby -v`、`bundle -v`、`bundle install`、起動の順番がコードブロックで区別されている。
- `app.rb` の途中状態と完成状態が両方あり、自分のコードを照合できる。
- `/` と `/movies` を両方開くため、パスを変えると別のルートが動くことを確認できる。
- リダイレクト後のアドレスバー、Network パネル、ターミナルログという三つの確認場所がある。
- 次章で何を作るかが最後に分かる。
