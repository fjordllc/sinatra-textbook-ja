# 総評

Sinatra を起動すること自体ではなく、HTTP メソッドとパスが Ruby の処理へ結び付くことを中心にしており、Rails へ進んだ後にも使える見方になっています。リダイレクトをサーバー内の関数呼び出しとせず、ブラウザを含む二往復で説明する点は、初学者時代に早く知りたかった内容です。

環境準備とアーキテクチャ説明は有用ですが、最初の成功体験までが長くなっています。起動ログに Puma が現れた直後に役割を説明すると、実際に見たものと概念を結び付けやすくなります。

# 良い点

- Sinatra 固有の DSL を、HTTP と Ruby を結ぶ道具として位置付けている。
- Rails も Rack の上で動くことを一文に留め、Rails の設計へ無理に寄せていない。
- `Gemfile` と `Gemfile.lock` の違い、`bundle exec` の理由が実務でも通用する説明になっている。
- 302 のレスポンスと、その後の GET を Network パネルで観察できる。
- 章終了時点のコードが小さく、後から問題を切り分けやすい。
- ERB、フォーム、JSON、method override を先取りせず、難易度が急に上がっていない。
