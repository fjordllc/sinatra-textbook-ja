# レビュー担当

FBC ベテランメンター

# 対象

第8章「リダイレクトは二つのリクエストをつなぐ」

# 総評

FBC で重視する PRG、Network タブ、method override の観察がまとまっており、提出課題へ知識を転用しやすい章になっている。第5章から使っていたリダイレクトにここで名前と意味を与える構成も自然である。

# 良い点

- PRG を「処理後の見た目」ではなく「状態変更と表示用 GET を分ける設計」として説明している。
- 登録、更新、削除の 3 パターンをそれぞれ観察対象にしている。
- Network タブでは POST と `_method`、Sinatra ログでは PATCH/DELETE を見るという説明が明確である。
- `GET /` のリダイレクトとの違いを扱っており、同じ `redirect` の意味の違いを説明できている。

# 改善が必要な点

## must

なし。

## should

- 問題: 一時的な比較コードを「想像します」として示しているが、実際に変更して試すのか、読むだけでよいのかが少し曖昧である。
- 理由: 初学者が完成コードを書き換えて戻せなくなる可能性がある。
- 修正案: この比較コードは写さず、完成コードには残さないと明確に書く。

## could

- 改善案: 303 の説明は現在の範囲で十分。リダイレクトステータスの比較は広げなくてよい。
