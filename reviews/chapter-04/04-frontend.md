# 総評

フォームの HTML は妥当です。各入力欄に `label` があり、`for` と `id` も対応しています。`select`、`textarea` の説明も初学者に必要な範囲に収まっています。JavaScript や高度な UI に広げていない点も良いです。

改善点は、フォーム送信ボタンの文言と CSS の完成確認です。`送信内容を確認` は第4章の一時状態としては正しいですが、章が進むと変更される可能性があるため、章末で「確認用」と明確にする必要があります。

# 良い点

- `label` と `input` / `select` / `textarea` の対応が適切。
- `textarea` に `rows` があり、複数行入力欄として分かりやすい。
- 状態を変える操作をリンクではなく `button type="submit"` にしている。
- 「一覧へ戻る」は状態を変えない移動なのでリンクになっている。
- CSS はフォームの視認性を上げる範囲に留まっている。

# 改善が必要な点

## must

### CSS の最終状態が章末で確認できない

- 問題: フォーム用のクラスを複数追加しているが、章末に CSS の完成状態がない。
- 問題になる理由: フォームの見た目と入力欄の幅は、CSS の追加が漏れると大きく崩れる。初学者が照合できる状態が必要。
- 修正案: 4.8 に CSS の追加部分を掲載する。全文が長すぎる場合は「第4章で追加した CSS」として示す。
- 対象箇所: 4.8

## should

### `button` とリンクを同じ見た目にしすぎている

- 問題: `.button-link` と `button` を同じスタイルにしており、リンクと送信操作の違いが見た目で分かりにくくなる可能性がある。
- 問題になる理由: 本書の方針ではリンクか送信かを区別する。第4章の「新しい映画を登録」は移動リンクだが、見た目はボタンに近い。
- 修正案: 現状でも許容範囲だが、本文中で「見た目はボタン風でも、HTML としてはリンクであり `GET /movies/new` を送る」と一文補足する。
- 対象箇所: 4.1

### `select` の初期値について補足するとよい

- 問題: `select` は最初の `option` が選ばれた状態になるが、本文では触れていない。
- 問題になる理由: 空欄送信を観察する話と、ジャンルだけは空にならない挙動の違いが分かりにくい。
- 修正案: このフォームでは最初の選択肢「アクション」が初期選択になると一文加える。
- 対象箇所: 4.4

## could

### `autocomplete` は扱わなくてよい

- 改善案: ブラウザの補完挙動はこの章の主題ではないため、属性追加は不要。
- 期待される効果: HTML フォームの基本に集中できる。
- 対象箇所: `views/new.erb`
