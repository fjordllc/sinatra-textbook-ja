# レビュー担当

FBC ベテランメンター

# 対象

第5章「JSON ファイルに映画を保存する」

# 総評

第4章の `params.inspect` から、JSON 保存、UUID、タイトル必須チェック、リダイレクトへ自然に進んでいる。FBC の Sinatra 課題で必要になる考え方を、映画図鑑という別題材で学べる構成になっている。

# 良い点

- `public/` に保存データを置かない理由が早い段階で説明されている。
- タイトル必須チェックをサーバー側で行い、`required` 属性だけに頼らない説明が入っている。
- 成功時と入力エラー時で、保存、リダイレクト、フォーム再表示の違いが明確である。
- `redirect` を先に使い、第8章で PRG として意味付ける流れが保たれている。
- 保存した利用者入力を表示するため、第5章で `h` ヘルパーを導入した判断は安全である。

# 改善が必要な点

## must

なし。

## should

- 問題: タイトル空欄時に JSON が変わらないことを確認する手順はあるが、読者がどのタイミングでファイルを開けばよいか少し曖昧である。
- 理由: 初学者はフォーム送信後に画面だけを見て、保存ファイルの変化を見落としやすい。
- 修正案: 「送信前に `data/movies.json` を開いておき、送信後に追加されたかを見る」といった観察方法を短く足す。

## could

- 改善案: `JSON.pretty_generate` を使う理由として、Git の差分や人間の確認がしやすいことを一文足してもよい。
- 期待される効果: 保存ファイルを読む教材としての意図が伝わりやすくなる。

# 疑問点

- 第5章の登録成功後は一覧へ戻す方針で問題ない。第6章で詳細画面へ変えることが本文にも明記されている。
