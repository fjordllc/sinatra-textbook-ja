# レビュー担当

フロントエンドエンジニア

# 対象

第9章「利用者の入力はそのまま HTML にしない」

# 総評

HTML の本文、属性値、`textarea` という出力先ごとの差を扱っている点がよい。フォームで入力値を戻す場面にも XSS が関係することを学べる。

# 良い点

- 属性値を壊す `"><script>...` の例がある。
- `textarea` を閉じる `</textarea>` の例がある。
- `white-space: pre-line` と Ruby 側の HTML 生成を分けて説明している。
- 完成コードで `h` が戻っていることを確認させている。

# 改善が必要な点

## must

なし。

## should

- 問題: `select` の `genre` も利用者入力として扱うと書いているが、画面上は選択肢から選ぶため、他項目と同じ自由入力ではない。
- 理由: 開発者ツールや直接リクエストでは変えられるが、初学者には違和感が出る可能性がある。
- 修正案: 画面では選択肢から選ぶが、リクエストとして届く値なので表示時は同じくエスケープする、と補足する。

## could

- 改善案: `option` の表示は現在のコードでは固定文字列なので、深追いしなくてよい。
