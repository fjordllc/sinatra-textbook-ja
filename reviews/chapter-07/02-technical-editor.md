# レビュー担当

技術書のベテラン編集者

# 対象

第7章「編集と削除で CRUD を完成させる」

# 総評

CRUD の残りである更新と削除を一章で扱っているが、説明の順序は自然である。編集画面、更新処理、削除フォーム、削除処理、観察の流れが読者の操作順に沿っている。

# 良い点

- CRUD 表で現在地を示してから本題に入っている。
- 登録フォームと編集フォームをあえて共通化しない理由が明記されている。
- Network タブとログの見え方の違いが章末確認に反映されている。
- 削除後の遷移先の理由が本文にある。

# 改善が必要な点

## must

なし。

## should

- 問題: 第8章で PRG を扱うため、第7章で更新・削除後に直接 HTML を返さない理由を詳説しないことはよいが、「ここでは使い、第8章で意味付けする」橋渡しがやや弱い。
- 理由: 更新と削除でも 303 が出るため、第8章の役割を明確にしておく必要がある。
- 修正案: 更新成功後・削除成功後のリダイレクトの説明に、第8章で再送信防止として捉え直すと追記する。

## could

- 改善案: CRUD 表の英語に読み仮名は不要。
