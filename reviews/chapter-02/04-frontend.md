# 対象

- 第2章「Sinatra をはじめる」
- 図 2-1
- mdBook のデスクトップ表示と 500 px 幅表示

# 総評

この章では意図的に HTML をまだ作らないため、フォームや画面構造のレビュー対象はありません。その境界は明確で、単なる文字列レスポンスを HTML 文書と混同させていません。生成ページの本文、コード、表はデスクトップと 500 px 幅の両方で欠落や重なりなく表示されています。

図 2-1 は横長の四要素で、狭い画面では画像全体が縮小されます。図中の日本語を本文と同じように読ませるには、スマートフォン相当の幅でも文字サイズを保てる構成が必要です。

# 良い点

- 図に可視キャプションと具体的な代替テキストがある。
- 見出し、本文、インラインコード、コードブロック、表に横方向の欠落や重なりがない。
- URL とコマンドをコードとして区別し、読者が操作対象を識別しやすい。
- 画面だけでなく Network パネルを観察するため、ブラウザ上の見た目と HTTP の動作を分けている。
- HTML と ERB は次章へ残し、文字列レスポンスの段階で不完全なマークアップを教えていない。

## should

### 図 2-1 を狭幅でも読める比率へ変更する

- 対象: `manuscript/assets/fig-2-1.svg`
- 問題: 4個の箱を横一列に並べた約 8:3 の図は、本文幅が約 460 px のとき図中テキストも約3分の1まで縮小されます。
- 理由: `alt` は画像が表示できない場合の代替であり、表示された小さい文字を読むための代替ではありません。
- 修正案: ブラウザ、Puma、Rack の境界、Sinatra を縦方向に配置するか、2段に再構成する。Rack は実行主体と異なる見た目にし、図中本文が狭幅でも読めるサイズになるようにする。

### 図と本文の対応を一文で示す

- 対象: `manuscript/part1/chapter2.md:118`
- 問題: 図の直後は各役割の説明に入りますが、矢印の往復をどの順番で読むかは代替テキストにしかありません。
- 理由: 視覚的な順序を本文でも説明すると、画像を拡大できない読者や図を読み取りにくい読者にも同じ情報が届きます。
- 修正案: リクエストはブラウザから Sinatra へ、レスポンスは逆向きへ戻る、と本文の最初に一文置く。
