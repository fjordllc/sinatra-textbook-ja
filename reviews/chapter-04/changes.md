# 修正記録

# 対象

第4章「フォームはリクエストを作る」

## 対応した指摘

### 指摘: 章末の完成状態に `views/index.erb` と CSS が不足している

- 出典:
  - `01-fbc-mentor.md`
  - `02-technical-editor.md`
  - `04-frontend.md`
  - `05-beginner.md`
- 対応: 4.8 に `views/index.erb` の完成コードと、第4章で追加した CSS を掲載した。
- 理由: 一覧から登録画面への導線とフォーム CSS も第4章の編集対象であり、初学者が章終了時点の状態を照合できる必要があるため。

### 指摘: `params.inspect` が第4章だけの確認用であることが弱い

- 出典:
  - `03-ruby-sinatra.md`
  - `06-fbc-graduate.md`
- 対応: 4.5 と 4.8 に、第4章だけの確認用コードであり、第5章で保存処理とリダイレクトへ置き換えると明記した。
- 理由: `params.inspect` を通常の完成レスポンスとして覚えさせないため。

### 指摘: HTML フォームの `method` 説明を限定する

- 出典:
  - `02-technical-editor.md`
- 対応: 4.7 を「HTTP リクエストとしてサーバーへ送る HTML フォームでは」と限定した。
- 理由: `dialog` への補足と矛盾せず、HTTP リクエスト送信としての `GET` / `POST` に集中させるため。

### 指摘: `params` が文字列キーであることを明確にする

- 出典:
  - `03-ruby-sinatra.md`
  - `05-beginner.md`
- 対応: 4.3 に、`params` はハッシュのようにキーを指定して値を取り出せること、本書では `params["title"]` のように文字列キーで扱うことを追記した。
- 理由: Ruby 学習済みの読者が `params[:title]` や `params.title` と混同しないようにするため。

### 指摘: `content_type :text` を Network 観察と結び付ける

- 出典:
  - `03-ruby-sinatra.md`
- 対応: 4.6 の確認表に、Response Headers の `Content-Type: text/plain` を追加した。
- 理由: 第3章から続く `Content-Type` の観察を継続するため。

### 指摘: ボタン風リンクの意味を補足する

- 出典:
  - `04-frontend.md`
- 対応: 4.1 に、見た目はボタン風でも HTML としてはリンクであり、`GET /movies/new` を送ると追記した。
- 理由: 見た目と HTTP 上の意味を混同させないため。

### 指摘: `select` の初期選択を補足する

- 出典:
  - `04-frontend.md`
- 対応: 4.4 に、最初の選択肢「アクション」が初期状態で選ばれていると追記した。
- 理由: 空欄送信の説明と、ジャンルが空欄にならない挙動を区別するため。

### 指摘: 空欄送信の例を入れる

- 出典:
  - `01-fbc-mentor.md`
  - `05-beginner.md`
- 対応: 4.5 に、タイトルを空欄で送ると `"title" => ""` のように空文字として届くことを追記した。
- 理由: 第5章のタイトル必須チェックへ自然につなげるため。

### 指摘: Form Data と `params` の順序は重要ではない

- 出典:
  - `06-fbc-graduate.md`
- 対応: 4.5 に、表示順ではなくキーと値が届いていることを見ると追記した。
- 理由: `params.inspect` の表示順に意味があるという誤解を防ぐため。

### 指摘: `POST` は安全という誤解を潰す

- 出典:
  - `06-fbc-graduate.md`
- 対応: 4.6 に、`POST` でも Network パネルで送信内容を確認でき、`POST` にしただけで秘密になるわけではないと追記した。
- 理由: POST の役割を「秘密にする方法」ではなく、サーバーへデータを送る HTTP メソッドとして理解させるため。

### 指摘: 送信後に戻る方法を補足する

- 出典:
  - `05-beginner.md`
- 対応: 4.5 に、確認用レスポンスからはブラウザの戻るボタンでフォームへ戻れると追記した。
- 理由: 一時的な確認画面で読者が迷わないようにするため。

## 採用しなかった指摘

### 指摘: `autocomplete` を扱う

- 出典:
  - `04-frontend.md`
- 理由: この章の主題はフォームから HTTP リクエストを作ることにある。ブラウザの入力補完属性へ広げると、説明範囲が散るため採用しない。

## 新たな設計判断

- 第4章では `params.inspect` の画面からブラウザの戻るボタンで戻る一時的な流れを許容する。第5章で保存後の画面遷移へ置き換える。
- 第4章の章末コードでは、全文ではなく「第4章で追加した CSS」を掲載する。第3章までの CSS はすでに前章で照合済みであり、重複を避けるため。
