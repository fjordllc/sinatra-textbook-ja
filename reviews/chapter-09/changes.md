# 修正記録

## 対応した指摘

### 確認用データを残さない注意

- 対象レビュー: `01-fbc-mentor.md`
- 対応: 危険な文字列を登録した確認用データは削除するか、退避した `data/movies.json` へ戻すと追記した。
- 理由: 危険な確認用データを残したまま次章へ進むことを防ぐため。

### XSS は JavaScript だけではない

- 対象レビュー: `02-technical-editor.md`
- 対応: JavaScript 実行だけでなく、タグ構造や属性値が壊れることも問題だと追記した。
- 理由: `<script>` だけを防げばよいという誤解を避けるため。

### `Rack::Utils.escape_html` の範囲

- 対象レビュー: `03-ruby-sinatra.md`
- 対応: `h` は HTML 本文、属性値、`textarea` に文字として表示する範囲で使うと補足した。
- 理由: JavaScript 文字列や URL など別文脈でも万能だと誤解しないようにするため。

### ジャンル値の扱い

- 対象レビュー: `04-frontend.md`
- 対応: ジャンルは画面では選択肢だが、リクエスト値として届くため表示時は同じくエスケープすると追記した。
- 理由: 選択式の値もサーバー側では信用しすぎないことを伝えるため。

### アラートが出ない場合の確認

- 対象レビュー: `05-beginner.md`
- 対応: アラートが出なくても、レスポンス HTML に `<script>` がそのまま入っていれば問題だと追記した。
- 理由: アラート表示の有無だけに学習の成否を依存させないため。

### 第10章への橋渡し

- 対象レビュー: `06-fbc-graduate.md`
- 対応: 次章では URL で指定された映画 ID も信用しすぎないことを扱うと追記した。
- 理由: XSS から 404 へ自然につなげるため。

## 採用しなかった指摘

### CGI.escapeHTML との比較

- 理由: 本書では `Rack::Utils.escape_html` を呼び出す `h` ヘルパーへ統一するため。

### XSS 攻撃手法の追加

- 理由: 本章は攻撃手法の網羅ではなく、出力文脈とエスケープの基本に絞るため。

## 新たな設計判断

- 第9章では危険なコードも危険なデータも完成状態に残さない。確認用の変更は、章内の一時的な作業として扱う。
