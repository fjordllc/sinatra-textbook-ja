# レビュー統合

## 対象

第9章「利用者の入力はそのまま HTML にしない」

## 総評

6 観点すべてで、章の目的と構成は妥当と判断された。未解決の `must` はない。第5章で導入した `h` ヘルパーを、危険な表示との比較で意味付けする章になっている。

## must

なし。

## should

- 確認用の危険なデータを残さず、削除するか JSON を戻す注意を追加する。採用。
- XSS は JavaScript 実行だけでなく、HTML のタグ構造や属性値を壊す問題でもあると補足する。採用。
- `Rack::Utils.escape_html` は本書で扱う HTML 本文・属性値・`textarea` の範囲で使うと補足する。採用。
- ジャンルは画面では選択肢だがリクエスト値なので、表示時は同じくエスケープすると補足する。採用。
- アラートが出ない場合でも、レスポンス HTML に `<script>` が残っていれば問題だと補足する。採用。
- 第10章へ、URL の ID も信用しすぎないという橋渡しを追加する。採用。

## could

- CGI.escapeHTML との比較は採用しない。`Rack::Utils.escape_html` に統一するため。
- XSS 攻撃手法の追加例は採用しない。出力文脈とエスケープに絞るため。
- OWASP の深掘りは章末リンクへ回す。

## 対応後の確認観点

- 完成コードに危険な変更が残っていないこと。
- `views/*.erb` の利用者入力表示が `h` を通していること。
- 確認用データが `data/movies.json` に残っていないこと。
