# 対象

第3章「HTML をレスポンスとして返す」

- 原稿: `manuscript/part2/chapter3.md`
- コード: `app.rb`, `views/layout.erb`, `views/index.erb`, `public/stylesheets/application.css`
- 章設計: `docs/chapter-designs/chapter-03.md`

# 総評

HTML の構造は素直で、`layout.erb` と個別ビューの責務分離も適切です。表には `thead`、`tbody`、`th scope="col"` があり、最低限のアクセシビリティも押さえています。CSS も教材の目的に合う控えめな量です。

改善点は、スマートフォン幅で表が横に詰まる可能性と、章末の完成ビュー確認の不足です。初学者向け教材では、見た目が崩れているとコードの正誤判断が難しくなるため、最低限のレスポンシブ対策を入れておくとよいです。

# 良い点

- `layout.erb` に文書全体の構造を集約している。
- `lang="ja"`、`meta charset`、`meta viewport` がある。
- サイトタイトルが `/movies` へのリンクになっており、一覧へ戻る導線の基礎になっている。
- 表のヘッダーに `scope="col"` がある。
- CSS は一覧、本文、ナビゲーションの区切りに絞られている。

# 改善が必要な点

## must

### 最終的な `layout.erb` と `index.erb` を本文で確認できない

- 問題: 最終コードとして `app.rb` だけが掲載され、HTML の最終構造を読者が確認できない。
- 問題になる理由: HTML の不正な入れ子や `layout.erb` との重複は、初学者が気づきにくい。章のテーマが HTML と ERB なので、ビューの完成状態は必須。
- 修正案: 3.10 に `views/layout.erb` と `views/index.erb` の完成コードを掲載する。
- 対象箇所: 3.10

## should

### 狭い画面で表がはみ出したときの最低限の対策がほしい

- 問題: `.movie-table` が幅 100% で列幅の逃げ場が少なく、長いタイトルが入ると狭い画面で読みづらくなる可能性がある。
- 問題になる理由: CSS の詳細は扱わない方針でも、教材画面がスマートフォン幅で破綻すると学習体験を損なう。
- 修正案: `.movie-table` に `display: block; overflow-x: auto;` を入れるか、ラッパー要素で横スクロールさせる。シンプルさを優先するなら CSS だけでよい。
- 対象箇所: `public/stylesheets/application.css`, 3.8

### `href="/stylesheets/application.css"` の説明に Network との接続を入れる

- 問題: CSS を読み込む `link` 要素と、Network パネルに現れる CSS の `GET` が少し離れている。
- 問題になる理由: HTML の `link` が新しいリクエストを発生させることは、初学者にとって重要なつながりである。
- 修正案: 3.7 の `link` 要素説明の直後に「この `href` を見てブラウザが CSS を取りに行く」と一文入れる。
- 対象箇所: 3.7

## could

### `site-title` の色はリンクであることが分かるよう維持する

- 改善案: 現在の `text-decoration: none` は見た目を整えるにはよいが、リンクであることを失いやすい。ホバー時の下線を追加してもよい。
- 期待される効果: ナビゲーションとしての認識が少し上がる。
- 対象箇所: CSS
