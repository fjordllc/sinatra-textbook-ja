# 総評

フォームのどこを見ると送信先やキーが分かるのかが説明されていて、手を動かしやすい章です。`id` と `name` の違いは、これまで曖昧だったので助かります。Network パネルで Form Data と `params.inspect` を比べる流れも分かりやすいです。

ただ、最後に自分のコードが合っているか確認するとき、`views/index.erb` と CSS がないので少し不安です。また、`params.inspect` が本当に保存ではないことは分かりますが、章末コードに残っているため、次章で変わるともう一度言ってほしいです。

# 良い点

- 第4章から始めるコマンドがあって迷わない。
- フォームの `action`、`method`、`name` の表が分かりやすい。
- `id` と `name` の違いが具体例で説明されている。
- `textarea` は `value` 属性ではない、という注意が分かりやすい。
- Network パネルで何を見るかが表になっている。

# 改善が必要な点

## must

### 最後に変更したファイルを全部確認したい

- 問題: `views/index.erb` に追加したリンクと、CSS の追加分が章末に出てこない。
- 問題になる理由: 自分のファイルが正しいか確認できない。
- 修正案: 4.8 に `views/index.erb` と CSS の追加部分を載せる。
- 対象箇所: 4.8

## should

### 空欄で送ったときの例があると分かりやすい

- 問題: 「空欄のまま送るとどう届くのかも材料」とあるが、実際にどう表示されるかはない。
- 問題になる理由: 第5章の入力チェックにつながるなら、空文字が届くことを見たい。
- 修正案: タイトルを空欄で送ると `"title" => ""` のように表示されることを短く書く。
- 対象箇所: 4.5

### `params["title"]` の角括弧が何をしているか少し説明してほしい

- 問題: Ruby のハッシュで学んだ形ではあるが、`params` が何者かまだ少し不安。
- 問題になる理由: `params.title` のように書くのか迷うかもしれない。
- 修正案: `params` はハッシュのようにキーを指定して値を取り出せる、と一文追加する。
- 対象箇所: 4.3

## could

### 送信後に戻る方法を補足してほしい

- 改善案: `params.inspect` の画面からはブラウザの戻るボタンでフォームに戻れる、と書いてもよい。
- 期待される効果: 一時的な確認画面で迷いにくくなる。
- 対象箇所: 4.5
