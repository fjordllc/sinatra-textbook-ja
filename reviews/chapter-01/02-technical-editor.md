# 改善が必要な点

## must

### 初出の専門用語が「はじめに」に集中している

- 対象: `manuscript/preface.md:21`, `manuscript/preface.md:31`
- 問題: `CRUD`、`PRG`、`XSS`、`REST`、`リソース`、`URI` が短い範囲に並びます。
- 理由: Web アプリケーション未経験者にとって、本書の案内を理解する前に未知語を処理する負荷が発生します。
- 修正案: 到達点は日常語で先に示し、残す略語には短い説明を添える。REST の段落は「事前学習は不要」と先に伝え、専門語の列挙を減らす。

### 第1章で `リソース` が未定義のまま使われている

- 対象: `manuscript/part1/chapter1.md:145`
- 問題: この章の用語として説明していない `リソース` が、節の結論に現れます。
- 理由: REST の事前学習を必須としていない方針と矛盾します。
- 修正案: この章では「URL が映画の一覧と一件の映画のどちらを指すか」と具体的に書く。`リソース` は必要になる章で定義する。

## should

### 図番号とキャプションを本文に出す

- 対象: `manuscript/part1/chapter1.md:59`
- 問題: ファイル名は `fig-1-1.svg` ですが、読者に見える図番号とキャプションがありません。
- 理由: 後の本文やレビューで図を参照しにくく、FBC Press の図版計画との対応も見えません。
- 修正案: `figure` 相当の Markdown/HTML と「図 1-1 リクエストとレスポンスの往復」というキャプションを置く。

### `file://` の例が OS 固有であることを明示する

- 対象: `manuscript/part1/chapter1.md:28`
- 問題: `/Users/...` は macOS のパスです。
- 理由: OSS 技術書として Windows や Linux の読者が、自分の表示との違いを誤りだと受け取る可能性があります。
- 修正案: 「macOS では次のように表示されます。OS によってパスは異なります」と一文添える。

## could

### 学習ゴールの見せ方をシリーズ内で揃える

- 改善案: 太字ラベルを採用するなら、今後の章でも同じ位置と粒度に揃える。ただし節見出しとして固定化はしない。
- 期待される効果: 読者とレビュアーが章の判断軸をすぐ確認できる。
