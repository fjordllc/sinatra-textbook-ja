# レビュー担当

FBC 卒業生の現役 Web エンジニア

# 対象

第5章「JSON ファイルに映画を保存する」

# 総評

FBC 受講時につまずきやすい、保存場所、ID、入力チェック、リダイレクト、エスケープの入口が一章にまとまっている。Rails に進む前に「自分でやると何が起きているか」を理解する教材としてよい。

# 良い点

- `params` 全体を保存せず、必要なキーだけをハッシュにする点が実務的にもよい。
- UUID を使うことで、削除後の ID 再利用や同名タイトル上書きの誤解を避けられている。
- `public/` と保存データの違いが、FBC のレビューで頻出する誤解を自然に防いでいる。
- `h` ヘルパーを第5章へ前倒ししたことで、安全でない保存済み入力表示を章またぎで残していない。
- ファイル保存の限界を第12章へ渡す布石がある。

# 改善が必要な点

## must

なし。

## should

- 問題: `redirect "/movies"` が 303 を返すことを確認しているが、第8章で何を追加で学ぶのかが少し薄く見える可能性がある。
- 理由: 先に 303 が出るなら、第8章の役割はステータスコードの初出ではなく、再送信防止という設計意図の理解になる。
- 修正案: 第5章では「ここでは仕組みとして観察するだけで、なぜこの形にするかは第8章で扱う」と明記する。

## could

- 改善案: `data/movies.json` を手で編集すると JSON の構文エラーが起きることを、デバッグ章への予告として短く触れてもよい。
- 期待される効果: 実際にファイルを開く読者が、カンマ抜けなどで詰まったときに原因を想像しやすくなる。

# 疑問点

- 第6章で登録後の遷移先を詳細へ変えるため、第5章の一覧遷移を「仮の完成」として見せすぎないことに注意したい。
