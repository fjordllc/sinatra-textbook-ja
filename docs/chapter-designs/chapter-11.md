# 第11章 章設計: 動かないときは境界を見る

## この章の目的

映画図鑑が思ったとおりに動かないとき、画面だけを見て推測するのではなく、ブラウザ、HTTP、Sinatra、ERB、JSON ファイルの境界で事実を集める方法を学ぶ。

## 読了後にできるようになること

- 症状を短い再現手順にできる。
- ブラウザの表示と Network タブの事実を分けて確認できる。
- Sinatra のログから、届いたルート、HTTP メソッド、ステータスコードを確認できる。
- `params` と `data/movies.json` を見比べ、保存前後のどこで問題が起きたかを切り分けられる。
- ERB のエラーを読み、`layout.erb` と各ビューの役割を確認できる。
- 404 と 500 を混同せず、最初に見る場所を選べる。

## 必要な前提知識

- 第10章までの映画図鑑の完成状態。
- Network タブで URL、メソッド、ステータスコード、Form Data を見る方法。
- Sinatra のログがターミナルへ出ること。

## サンプルアプリへ加える変更

完成コードに残す変更は行わない。必要に応じて一時的な確認例を示すが、確認後は元に戻す。

## 観察する対象

- 画面に何が表示されているか。
- Network タブのリクエスト、レスポンス、ステータスコード。
- Sinatra のログ。
- `params` に届くキーと値。
- `data/movies.json` の保存内容。
- ERB のエラーメッセージと行番号。

## この章では扱わないこと

- テストコード。
- ログ監視や本番運用。
- 高度な例外処理。
- デバッガの詳しい使い方。

## 章固有の設計判断

よくある失敗を答えとして列挙するのではなく、症状ごとにどこから事実を集めるかを示す。第12章へ、JSON ファイル保存の限界を考える前提を渡す。
