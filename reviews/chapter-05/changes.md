# 修正記録

## 対応した指摘

### 指摘: JSON ファイルの変化を観察する手順を具体化する

- 対象レビュー: `01-fbc-mentor.md`
- 対応: 章末の確認手順を「送信前後で `data/movies.json` を開く」表現へ変更した。
- 理由: 画面遷移だけでなく、保存ファイルの変化を見る章であることを明確にするため。

### 指摘: `File.join(__dir__, ...)` の意図を補足する

- 対象レビュー: `02-technical-editor.md`
- 対応: どのディレクトリから起動しても `app.rb` から見た `data/movies.json` を指せる、と説明を追加した。
- 理由: 初学者が `__dir__` を単なる決まり文句として覚えないようにするため。

### 指摘: 壊れた JSON やファイル欠落は範囲外だと明記する

- 対象レビュー: `03-ruby-sinatra.md`
- 対応: この章では `data/movies.json` が存在する前提で進め、壊れた JSON の切り分けは第11章と付録で扱うと追記した。
- 理由: 例外処理へ範囲を広げずに、読者の疑問だけを先回りするため。

### 指摘: エラーメッセージ領域に `role="alert"` を付ける

- 対象レビュー: `04-frontend.md`
- 対応: `views/new.erb` と本文中の完成コードへ `role="alert"` を追加した。
- 理由: 詳しいアクセシビリティ説明は避けつつ、エラー表示として自然な HTML にするため。

### 指摘: `JSON.parse` と `JSON.pretty_generate` を対比する

- 対象レビュー: `05-beginner.md`
- 対応: `parse` は JSON 文字列から Ruby へ、`pretty_generate` は Ruby から JSON 文字列へ変換すると追記した。
- 理由: 読み込みと書き込みで使うメソッドを混同しにくくするため。

### 指摘: 第8章の役割を補足する

- 対象レビュー: `06-fbc-graduate.md`
- 対応: 第5章ではリダイレクトを仕組みとして使い、状態変更後にこの形にする理由と再送信防止は第8章で扱うと追記した。
- 理由: 第5章で 303 を観察できるため、第8章の役割を PRG の意味付けに置くため。

### 指摘: `JSON.pretty_generate` を使う理由を補足する

- 対象レビュー: `01-fbc-mentor.md` の `could`
- 対応: 保存された JSON を人間が読みやすく、教材中で確認しやすいと説明した。
- 理由: ファイルを開いて確認する章の目的に合うため。
